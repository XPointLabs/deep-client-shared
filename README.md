# Deep Client Shared

`RefreshContactRouteAsync` renews the actual owned permanent publication through
its existing protected saga, then advertises the exact next route through an
existing mutually consented ratcheted conversation and a CURRENT reverse mailbox
route. Scheduling reopens actual native advertised history and the common authored
root: unchanged advertisement creates no event; unfinished control selects its
original operation. Authoring, encryption, Store and recipient receive/ACK retain
their separate independent checks. No new journal/schema or counter family,
contact or account is introduced; a new control uses the existing owned counters
and ratchet. Expired routes/XUR never acquire permission.
`ReadContactRouteHealthAsync` exports only three denial-only Boolean diagnostics
from actual authenticated history and fresh time, never descriptors/capabilities.
These predicates cannot authorize delivery. A missing live reverse route plus
expired update rendezvous remains unavailable; no public resolver fallback exists.
See the [contact update owner](../docs/architecture/CONTACT-AND-GROUP-PROTOCOL-V1.md#10-contact-route-and-device-updates).

New-work Deposit renewal does not repeatedly replace a still-live grant already
at its exact route's five-record signed expiry ceiling: the same route cannot
yield more lifetime. Shorter issuer-limited grants still renew; any pending
successor resumes its exact request. This is scheduling only. All ordinary
grant/route/currentness checks remain, and route renewal is still separate.

`DeepIdV2ClientNetworkSession.EstablishedMessagingSource` supplies the existing
bounded working public-authority scope to serial established text, attachment
and group commands. QueueText/RetryText and attachment queue/send also open a
command scope, including for nonpersistent callers. Consent, authoring, native
send and delivery borrow one coherent endpoint pair while independently rejoining
actual protected state/time; transport objects receive that same child source.
There is no new lifetime, private-state cache or stale fallback.
Serial hosts call `DiscardUncapturedGroupAuthorityAsync` before independent
network/contact/receive/ACK work can advance shared network custody. This ends
only uncaptured public reads, never a captured loan. Fresh ACK remains independent.
The API retains its existing refresh/discard/maintenance method names; the
established-source property replaces the narrower group-only property without
a compatibility alias. Consumers must rebuild; no account/schema reset is needed.
See the [execution owner](../docs/architecture/TRANSPORT-NEUTRAL-MESSAGING.md#32-steady-state-execution-и-стоимость-проверки).

`DeepIdV2AccountService.GetConversationAsync` selects a canonical conversation
identifier from the actual protected catalog, then verifies that session's local
history/acceptance custody and catalog read-back. It does not open unrelated
sessions or grant network/send/ACK authority; those operations still check their
own current protected state. Group flush uses catalog handles only for scheduling,
and independently verifies every nonempty native batch before delivery.

Connected default Store and mailbox-sync APIs perform at most one owned
continuation after typed `OutcomeUnknown`; raw fault-test seams stay single-attempt.
Every continuation reopens actual protected custody/current authority. Original
live requests remain exact; authenticated retirement/succession stays owner-only.
`ExactStoreResumes`, `ExactMailboxResumes` and `ExactRecoveryLeaseWaits` are
diagnostics, never receipt authority. See
[the retry owner](../docs/architecture/TRANSPORT-NEUTRAL-MESSAGING.md#82-retry-and-failover).

`SendGroupTextAsync` drains unfinished fanout rather than re-auditing every old
Store. Actual protected authored completion is only a scheduling hint, never a
receipt or authorization shortcut; unknown work keeps the full owned path.
`FlushGroupAsync` still performs complete historical original-batch verification.
No retained messages, receipts or audits are removed by this optimization. See
the [delivery owner](../docs/architecture/TRANSPORT-NEUTRAL-MESSAGING.md#81-state-machine).

ACK uses a newly acquired phase-local public context, independent of receive or
working group authority. Only repeated lookups inside that same ACK phase share
its proofs; all ordinary actual custody/time/effect fences remain mandatory.

The serial public composition pools Registry HTTPS connections for up to two
minutes (one minute idle), separately for each session/client. This changes
socket reuse, not proof reuse: every response retains nonce/signature/floor
verification, platform TLS with online revocation, explicit system proxy,
no redirects/cookies/decompression, and no proxy-to-direct fallback. Selected
ONION pinning and path isolation are not modified by this public-client pool.

Native ordinary-message preparation verifies the complete SQLCipher journal,
retained prefix, policy/schema and independent protected tip once in a single
read transaction, then selects exact replay custody, derives the retention
context and reads the current ratchet from that same snapshot. There is no
await, callback, mutation, private-state cache or reusable verification token
inside that snapshot. Commit, recovery and actual post-effect read-back retain
their independent fences; a later call must verify the database again. The
selected ONION entry socket uses TCP no-delay without changing its exact TLS
pin, current path checks, framing or retry classification.

Read-only protected aggregate access authenticates the actual complete file and
validates every slot's canonical encoding and byte bound, ordering and trailing byte,
but materializes separate value buffers only for requested slots. Unselected
malformed entries still reject the whole read; mutations still load the full
inventory. The full decrypted aggregate and temporary selected buffers are
wiped on exit, with no private-value, storage-authentication or currentness cache.

Local group history and original-batch scheduling read at most32 native operations
per synchronous SQL snapshot. Every batch verifies the entire journal/prefix,
including unselected rows, against the actual independent protected floor. No
await/callback crosses it; callers own/dispose all materialized values. Group
history preserves the original cross-scope order. Scheduling flags still cannot
authorize a Store, receipt, retry or semantic ACK.

Account registration may memoize only the pure, time-independent canonical
grammar predicate for six exact current group/ordinary/route/grant/send/read roots plus network, account
and instance. One account owner retains six32-byte digests, not private bytes,
decoded states, revisions, proof or storage-read verdicts. Every invocation still
authenticates actual storage; changed input/binding reruns the original decoder,
and failures are never remembered. Actual consumers still decode their needed
root afresh. SQL integrity, dynamic cancellation-owner joins, protected floors,
currentness and all effect/read-back fences remain independent and mandatory.
The additional four predicates cover otherwise unused registration decodes of
route, grant, send and read roots. Cross-root cancellation/retirement, compaction,
actual account/native floors and all dynamic joins are still parsed/rechecked.

`DeepIdV2ClientNetworkSession` may live across serial CLI commands. Its ordinary
`Source` retains independent acquisition; `EstablishedGroupSource` owns a bounded
public-only working group scope. `RefreshGroupAuthorityAsync` forces pre-effect
refresh; `MaintainGroupAuthorityAsync` revalidates and refreshes near the original
deadline. Hosts must serialize these with business work and dispose the session
on shutdown. Actual account/device/floors/time are rejoined on reuse; no private
loans or keys are retained by that scope. Semantics belong to the
[authority owner](../docs/architecture/ACCOUNT-DIRECTORY-TRANSPARENCY-V1.md#working-public-authority-and-delivery).

The current mailbox source contract follows
[DR81](../docs/survival-program/decisions/DR-0081-did2-mailbox-selection-grant-clean-break.md):
MCG3/MCP3/MAU3 and XMC2 only, with the signed PMS2 selection input checked by
the owned holder. DMB1 schema8 and protected grant/send journal version2 reject
older local state explicitly, including empty old journals; no migration or
automatic remint is provided. The new source is not yet a matched production
rollout or physical delivery qualification.

Publication successor coordination and the protected route-journal clean break
follow [DR79](../docs/survival-program/decisions/DR-0079-did2-publication-issuer-successor.md).
Clients retain publisher-bound prior receipts; server verification receives no
resolver-read capability. Older isolated QA journals require explicit reset,
not automatic migration. Matched issuer/peer repin and physical E2E remain open.

Portable .NET account, protocol-custody, persistence and service code for the
Windows and Android Deep clients. The MAUI app references
`src/Deep.Client.Shared/Deep.Client.Shared.Production.csproj`.

The DID2 clean-break is in progress. The production assembly may contain
historically named `*V1` components when their exact wire type is still part of
the DID2 profile (for example DMD1 or XPS1); that name alone is not permission
to accept DID1/DAB1 or the old `05…` account alias. The old Session-derived
client project and tests are not release evidence and will be removed as their
remaining useful coverage is moved to the production test project.

The current `DPH2` session ID is a 32-byte cryptographic ratchet/dedup value,
not the retired user-facing Session address. Initial messaging is fail-closed
until the exact DID2 sender, V2 contact/prekey publication, authenticated
ContactHello, durable inbox and ACK path are one verified graph.

The DID2 account service can now begin a DPH2 claim from its own exact
current DAB2/DMD1 proof and verify an exact DPK2 against the peer's fresh
DID2/DMD1 proof before using the protected, one-use device-agreement ledger.
MAUI cannot supply a callback-minted offering to this path. Both operations recheck
the proof's nonce window and exact protected directory floor; an older proof
cannot be reused after another lookup advances that floor. Completion returns
only Protocol's single-use preparation, not a private key or a delivery
receipt. The separately authenticated XPC1 claim remains mandatory before
the preparation can become a DPH2. MAUI publication/claim transport, session persistence and receive
composition remain separate release gates.
